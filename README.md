# WorkBuddy 用量状态栏

在 DeepSeek Harness（DSH）输入框下方查看会话用量、WorkBuddy 积分、模型费率和账号余额。桥接插件 dsh-connect-workbuddy 提供响应积分记录，本插件按响应编号将积分归入对应会话。

## 安装

需要 Node.js 22.15 或更新版本，以及 DSH 0.2.1-rc.2 至 0.3.0 之前的版本。

1. 下载项目并运行 npm run build。
2. 在 DSH 插件管理中安装此项目目录。
3. 启用 dsh-connect-workbuddy，并完成账号登录。重新启动 DSH 后，打开会话查看状态栏。

原插件更名后的数据处理方法见[迁移说明](docs/MIGRATION.md)。

## 显示范围

积分消耗卡片按模型展示本会话今天的积分，以北京时间零点分界。Token 统计卡的第二分组展示本会话累计积分，复用积分模型列表界面。“剩余积分”显示账号余额。状态栏积分数字与今日积分消耗卡片共用本会话今日积分；账号剩余积分显示在积分消耗统计分组中。

账号轮换后，同一会话的响应继续累计。插件根据响应编号关联积分；账号余额变化单独记录，用于核对账号收支。

上游记录中的实际积分优先使用。缺少实际积分时，已登记的模型可根据用量估算；每条请求先保留两位小数，再累计。计算条件、四类用量和已知限制见[积分计算](docs/ACCOUNTING.md)。

## Trae 费用边界

Trae 用量和实际积分独立统计。响应未提供可核对的缓存计费明细与人民币换算依据时，模型行显示“单价暂无依据”，不套用官方 API 参考价。混合渠道的人民币合计标为“费用估算（已知渠道）”，仅包含有参考计价依据的部分；仅有 Trae 时不显示人民币估价。

## 运行资源限制

会话解压和积分统计在独立工作线程执行，同一时间只计算一份结果；相同请求共用计算，等待请求最多八份。结果在内存中保留一分钟，命中缓存时直接返回。可重新计算的状态栏结果不再写入磁盘，实际积分和账号核对记录继续保存。

会话缓存只保留用量、模型、响应编号和时间，排除对话正文。缓存最多包含三十二份会话、合计十六 MiB；单次读取的压缩会话最多六十四 MiB，单帧解压最多十六 MiB，累计解压最多二百五十六 MiB。工作线程的 V8 老生代上限为二百五十六 MiB；这些限制共同约束内存使用，超限时返回统计暂不可用，不删除会话或积分。大于上限的会话需要后续接入增量读取，当前保留已有显示。

可见页面每分钟刷新一次，切换会话或模型时立即读取。历史响应积分按会话批量写入，已保存且未变化的记录跳过写入，后续更正仍会保存。页面隐藏后暂停定时刷新，未显示的会话状态栏不参与轮询；会话状态栏卸载后释放相应缓存。账号余额仍每分钟采样一次，余额和积分总额均未变化时跳过日志与快照写入。原始会话与历史积分保留。
