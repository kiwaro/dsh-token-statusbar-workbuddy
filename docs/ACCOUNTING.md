# 积分计算

## 用量分类

每条响应包含未缓存输入、缓存读取、缓存写入、输出四类 Token 数量。src/index.js 中的价格表按模型和请求时间计算参考费用；DeepSeek 的高峰、非高峰价格分别计算。价格表随项目维护，核对上游价格后再更新。

## 实际积分与估算

桥接插件的 response-credits.jsonl 保存响应编号、积分、账号和时间。本插件根据会话中的响应编号查找记录，同一响应只计一次。实际积分到达后替换该响应的估算。

缺少实际记录时，src/accounting.js 使用参考费用乘以已登记的换算系数：DeepSeek-v4.1-flash 为 100/7，来自 107 条历史响应；GLM-5.3-flash 为 18.603，来自 16 条历史响应。每条响应保留两位小数后累计。这些系数来自历史样本，上游费率改变后需要重新核对。

只有用量完整、数值有效、缓存写入为零且模型已登记时，插件才估算积分。其他请求保留为未匹配记录。缓存写入费用参与参考费用计算，其积分估算目前尚待补充。当前时间价格判断使用星期与时段，节假日安排需要补充。

## 会话与账号

当前会话按响应编号统计，排除创建时间之前的记录。北京时间当天的响应计入当前会话今日消耗。全部会话今日实际积分另行汇总，包括未打开的会话。

账号轮换改变请求使用的账号，响应编号继续用于会话关联。余额采样单独保存；余额变化用于核对账号收支。计费自动测试使用合成会话及多个账号记录，现场账号轮换情况见验证记录。
